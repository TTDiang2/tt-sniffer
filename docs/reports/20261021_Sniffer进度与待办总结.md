## 三、新增三项：PWA 重连 / 翻译统计 / 多 key 多模型

### 1. PWA 空闲后永久【重连中】

- 现象：页面放着不动一段时间，持续显示“重连中”且永远连不上；`Ctrl+Shift+R` 强刷后立刻恢复。
- 初步假设（待日志证实，不预先下结论）：
  - WebSocket 重连状态机在长时间断连后心跳/退避未重置，或退避达到上限后不再重试；
  - 强刷重置了前端连接对象后恢复。
  - PWA 为基础版（明确不做离线缓存），因此不太可能是 Service Worker 缓存旧 JS 导致，仍需排除。
- 待做：复现 → 抓取 WebSocket/控制台日志 → 定位重连循环与心跳代码 → 给根因 + 最小修复。

### 2. 翻译 / 戏谑评论成功率统计

- 目标：以**第一条成功翻译**为时间起点，统计：
  - 翻译成功率 = 成功翻译条数 / 总尝试条数（给出分母、分子、时间范围）；
  - 一句话戏谑评论成功率 = 成功加戏谑评论条数 / 已翻译成功条数（或总条数，口径待与用户确认）；
  - 失败原因分布（超时 / 401 / 429 / 解析失败 / 空返回 等）。
- 用途：为 3–5 个 key 池提供压测依据。
- 待做：从 `data/sniffer.db`（只读，不改 schema）拉统计 → 产出报表 → 再定 key 池规模与路由策略。

### 3. AI 多 key / 多模型配置（translate / comment / chat 三路）

- 目标：把“翻译”“一句话戏谑评论”“AI 对话分析”拆成三条独立通道，每条可配：
  - `platform` / `model` / `key`（3–5 个 key 池）/ `system_prompt`（可改，用于调戏谑程度）；
  - 轻量模型走翻译（省成本、快），更强模型走对话分析；
  - key 池轮换 + 降级策略；旧单 key 配置需兼容。
- 待做：先出**配置结构 + 迁移方案**给用户确认，再落地实现与测试（不直接跳实现）。
