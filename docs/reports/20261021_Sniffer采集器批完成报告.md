## 2. A：crypto_rss 时区修复

### 根因

RSS 的 `pubDate` 形如 `Tue, 20 Oct 2026 11:53:43 GMT`。旧代码直接去掉 `tzinfo`，把 GMT 钟面当成北京时间写入，整体早 8 小时。

### 修改

`app/collectors/crypto_rss.py`：

- `parse_rss(..., to_local=True)` 默认改为 `True`。
- 带时区时间先 `astimezone()` 转到本机时区，再 `replace(tzinfo=None)`。
- `fetch_crypto_rss` 显式传 `to_local=True`，与 `items.ts` 的本机 naive 时间口径一致。
- 保留 `to_local=False` 作为显式 UTC naive 兼容出口。

### 验证

`tests/test_crypto_rss.py` 新增 GMT 回归用例：

- 输入 `Tue, 20 Oct 2026 11:53:43 GMT`
- 期望本机时间 `2026-10-20 19:53:43`
- 测试用 `astimezone()` 动态计算期望值，兼容 CI 时区。

结果：`tests/test_crypto_rss.py + tests/test_rss.py` 共 **8 passed**。

### 范围说明

按任务书**未回填**历史损坏数据；任务书列出的 17 条历史记录仍保持原值，后续如需要应单独做一次性迁移。

## 4. C：宏观日历

### 实现

新增 `app/collectors/calendar.py`：

- 主源：`akshare.news_economic_baidu(date=YYYYMMDD)`
- 回退：`akshare.macro_info_ws`（华尔街见闻）
- FOMC：美联储官方 2026 会议日程，含 SEP 点阵发布标记
- 独立数据库：`data/macro.db`，不改 `data/sniffer.db` 结构

表结构严格按任务书：

```sql
macro_events(
  event_id TEXT PRIMARY KEY,
  ts_release TEXT NOT NULL,
  country TEXT NOT NULL,
  metric TEXT NOT NULL,
  period TEXT,
  prev REAL,
  forecast REAL,
  actual REAL,
  unit TEXT,
  revised_at TEXT,
  source TEXT,
  created TEXT
)
```

关键行为：

- `event_id = sha1(source|country|metric|period-or-date)[:16]`，稳定可复现。
- 国家映射：美国→US、中国→CN、欧元区→EU 等。
- 数值清洗、单位提取（末尾括号）、月份/季度 period 提取。
- 每日前瞻未来 7 天；每 30 分钟回看近两日补 actual。
- 首次启动回填 7 天，用于补近期 actual 和满足验收样本。
- PIT 规则：actual 首次写入后，forecast/prev 冻结，不再被后续抓取改写；actual 修订时更新 actual 并写 `revised_at`。
- 单日抓取 30s 超时；单日失败只跳过该日，不杀死循环。

FOMC 2026 日程：1/27-28、3/17-18（SEP）、4/28-29、6/16-17（SEP）、7/28-29、9/15-16（SEP）、10/27-28、12/8-9（SEP）。公布时间按会议最后一天次日 02:00（夏令时月份）或 03:00（冬令时）北京时间。

## 5. D：ZQ 利率快照

### 标的确认

`ZQ` 是 CME **30-Day Federal Funds futures**，不是 10 年期美债期货。

### 数据源

- CME 官方 JSON：`https://www.cmegroup.com/CmeWS/mvc/Settlements/Futures/Settlements/305/FUT?tradeDate=MM/DD/YYYY`
- 直连该接口返回 **403**（IP 被判定为抓取）。
- 改用 `https://r.jina.ai/` 只读镜像读取同一份 CME 官方 JSON，字段仍为 CME settlement。
- `app/collectors/rates_snap.py` 模块头注释已写明实际来源、403 情况和镜像回退。
- 备用 Yahoo 代码 `ZQZ26.CBT` / `ZQH27.CBT` 可用，但本批未实现，仅记录为后续备选。

### 实现

新增 `app/collectors/rates_snap.py`：

- 取 CME settlement 的前两个未空白月份：近月、次月。
- `implied_front = round(100 - settle_front, 4)`。
- 追加写 `data/rates_snap.jsonl`，按 `date` 去重。
- 无指定日期时，从昨天起向前最多找 8 天，避开周末/节假日。
- 每日北京时间 05:10 执行；启动时立即补一次。
- 字段：`date`、`settle_front`、`settle_next`、`implied_front`、`ts_snap`。

### 实测

`data/rates_snap.jsonl` 当前两行：

```json
{"date":"2026-10-19","settle_front":96.1175,"settle_next":96.075,"implied_front":3.8825,"ts_snap":"2026-10-21T15:28:41+08:00"}
{"date":"2026-10-20","settle_front":96.115,"settle_next":96.08,"implied_front":3.885,"ts_snap":"2026-10-21T15:28:45+08:00"}
```

人工对照 CME 页面 2026-10-20：OCT 96.1150、NOV 96.0800，与写入值一致；10-19 的 96.1175/96.0750 也与 CME JSON 一致。

### 测试

`tests/test_rates_snap.py` 4 项：近月/次月解析、空白行跳过、追加去重、连续日期。

结果：**4 passed**。

### 局限

- 直连 CME 被 403，当前依赖 Jina 只读镜像；镜像不可用时快照会失败并只记录状态，不会污染既有 JSONL。
- 该来源是 CME 官方 JSON 的镜像，不是交易所直连行情；如需严格“CME 延迟源”，需要可用的 CME 授权/代理出口。
