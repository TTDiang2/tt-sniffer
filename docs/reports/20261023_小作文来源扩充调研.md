# TT_Sniffer 多渠道“小作文”嗅探调研报告

> 调研时间：2026-10-23。方法：WebSearch/WebFetch 检索官方通报、项目仓库与社区实测；GitHub API 读取 star/最近推送；本机用 curl 对股吧、公众号、微博、雪球、小红书、韭研公社做未登录/低权限探测。star 数为当日快照。

## 一、结论先行

1. **微信群是“小作文”的源头，但没有合规的无人采集路径。** 个人微信没有官方消息 API；企业微信会话存档只覆盖企业自身会话，且需员工/客户告知同意，不适用于个人群。数据库解密、Hook、iPad 协议、群控都属于破解/外挂，明确不做。
2. **公开二级传播层足以支撑产品。** 小作文要影响价格，必然外泄到公众号、微博、雪球、股吧、韭研公社、财联社等；抓这些“泄漏点”，比追求群内首发更现实。
3. **落地排序：股吧详情补抓 → 韭研公社 → 公众号 RSS → 微博 → 雪球 → 小红书（条件性）→ 微信群（不做）。**
4. **“无人工”应定义为“无人值守 + 失效告警 + 可降级”，不是零维护。** 股吧、韭研、财联社可真正无人；公众号、微博、雪球、小红书都需要偶尔重登或换 cookie。

## 二、背景：传播链与监管态势

第一财经对股市“小作文”灰产的调查给出的链条是：**专人炮制 → 截图在微信群传播 → 股吧/外部平台转发 → 财经自媒体与公众号放大 → 游资点火 → 量化顺势放大**。一条谣言的月成本可低于 1 万元，小市值股票 3% 波动即可让提前布局者获利数十万元；AI 批量生成进一步降低了边际成本（[第一财经/凤凰网](https://ishare.ifeng.com/c/s/v002jlcQYvoBTtFkOZ1--kAJmec79RQ3L59yj4--mAeKr5zVc__)）。

监管已进入“全链条”阶段：2025-12-19 国家网信办会同证监会通报五类典型案例，其中第三类明确点名利用 AI 批量生成“标题党”“小作文”的账号并被关闭（[CAC](https://www.cac.gov.cn/2025-12/19/c_1767870959853194.htm)、[证监会](https://www.csrc.gov.cn/csrc/c100028/c7603320/content.shtml)）；2025-03 雪球用户编造弘信电子虚假信息致股价大跌，被行政拘留；2025-05 最高法、证监会明确“小作文”致损可民事索赔、构成犯罪追刑责。**TT_Sniffer 的定位必须是“聚合与标注工具”，不能成为谣言生成、荐股或二次传播工具。**

## 三、渠道逐个评估

### 3.1 微信公众号

- **公开获取**：文章 URL 本身可公开打开；RSS 侧有 Wechat2RSS（公开 300+ 公号，目标 24 小时内）、we-mp-rss、今天看啥等；搜狗微信只适合补充。
- **凭据/逆向**：微信读书扫码（Wechat2RSS、we-mp-rss、wewe-rss）；公众号后台 `token`+Cookie（约 2–3 天失效）；搜狗验证码。搜狗仅显示有限页、链接临时，不建议作为主通道。
- **反爬/封号**：`mp.weixin.qq.com/robots.txt` 实测 `Disallow: /`（仅少数路径允许）；冷请求会跳转 `wappoc_appmsgcaptcha`。本次用微信 UA+Referer 实测文章页返回 200，含 `js_content` 与 `createTime`，说明正文可得，但对 IP/UA 敏感。微信读书接口报 `-2041` 风控、`-2012` 会话过期。
- **合规边界**：不做批量抓取、不绕验证码、不共享公众号后台账号、不搬全文；只对用户给出的单篇 URL 做校验。腾讯诉斯氏案中，被告用 75 个微信号、多个代理 IP 绕过封禁抓取，被判赔 60 万元，法院明确引用 robots 协议（[判决评析](http://www.rongtailaw.com/newsitem/278565255)）。
- **正文/时间**：可得；`#js_content`、`var createTime` 稳定；图片多、页面重。
- **难度**：消费 RSS 0.5–1 天；自建 5–10 天且需约 72 小时重扫码；直接抓文章 1–2 天但脆弱。
- **是否值得**：值得，但**先消费现成 RSS，不自建全量**；选 20–50 个高价值公号即可。

### 3.2 小红书

- **公开获取**：单篇笔记 URL 可尝试；搜索必须登录；官方开放平台没有面向个人的公开内容搜索（蒲公英/千帆是营销与商家工具），第三方付费 API 均为非官方。
- **凭据/逆向**：`web_session` + `x-s/x-t/x-s-common` 签名；MediaCrawler 用浏览器上下文取签名，Spider_XHS 用 Node 计算签名；cookie 寿命短。
- **反爬/封号**：签名短时有效、设备指纹、行为建模；本次搜索页只返回登录壳，笔记 URL 302 到“当前笔记暂时无法浏览”；`robots.txt` 为 `User-agent: * Disallow: /`；封号/限流风险高。
- **合规边界**：只做公开笔记；**不做群聊、私信、模拟真人互动、验证码绕过、账号池**；群消息涉及通信秘密，平台也已将群聊纳入重点治理场景。
- **正文/时间**：详情 API 可得标题、正文、时间、互动；搜索列表只有摘要，时间常为相对时间。
- **难度**：5–10 天且维护成本高；付费 API 1–2 天，但依赖灰色数据源。
- **是否值得**：条件性，最后做；除非明确需要散户截图、年轻用户舆情。

### 3.3 微信群（含文件/图片转发）

- **公开获取**：无。企业微信“会话内容存档”仅企业自身、需确认函与员工/客户同意，只覆盖企微，不覆盖个人微信群（[官方文档](https://developer.work.weixin.qq.com/document/path/91774)）。
- **凭据/逆向**：不存在合规凭据；数据库解密（WeChatMsg，42.1k star）、Hook、Wechaty/iPad 协议、群控均属破解/外挂。
- **反爬/封号**：微信安全中心 2024 年外挂公告明确阶梯封号；法律上可能触犯刑法 285 条“非法获取计算机信息系统数据”、侵犯公民个人信息、通信秘密；市场监管总局曾查处破解微信数据库监控聊天的私域软件案，江苏法院也有扫号软件刑事案。
- **合规边界（明确不做）**：**不做群监控破解、协议破解、数据库解密、群控、群内机器人、私聊抓取、文件批量导出。**
- **正文/时间**：只有自己设备上已落地的文件/图片可解析；文本不可得。
- **难度**：N/A；本地文件 watcher 2–3 天，但需人工保存/转发，不是无人。
- **是否值得**：不做。替代方案是公开二级源 + 盘口异动反推 + “30 秒人工转发到机器人/邮箱”的兜底入口。

### 3.4 微博

- **公开获取**：热搜、关键词搜索、用户时间线；`s.weibo.com`、`m.weibo.cn`；RSSHub；官方开放平台权限有限。
- **凭据/逆向**：visitor cookie 或登录 cookie。本次 `weibo.com/ajax/side/hotSearch` 返回 403，`s.weibo.com` 跳 visitor passport，`m.weibo.cn` 302；无 cookie 不可用。
- **反爬/封号**：403/418/432、频控、cookie 过期、账号封禁；长文需二次展开。
- **合规边界**：只公开博文；不抓私信/非公开内容；不批量存储、转售；`robots.txt` 基本 `Disallow: /`；微博诉蚁坊案判赔 528 万元，法院区分公开/非公开数据，抓取登录后数据并全文展示被认定不正当竞争（[案例](https://m.21jingji.com/article/20230424/herald/2fe8e7493530e91a02563b74a298aaf2.html)）。
- **正文/时间**：全文、精确时间、作者、转评赞可得。
- **难度**：3–5 天；需 cookie 健康检查与降频。
- **是否值得**：值得，公共放大层覆盖最好。

### 3.5 雪球

- **公开获取**：热帖、用户时间线、搜索；RSSHub 的雪球路由需 `XUEQIU_COOKIES`；pysnowball 主要做行情/财务，不做帖子。
- **凭据/逆向**：`acw_tc` + `xq_a_token`，后者由首页 JS 生成。本次仅带 `acw_tc` 时热帖 API 返回 WAF 挑战页，`api.xueqiu.com` 返回 `400016`，确认必须有有效 token。
- **反爬/封号**：WAF、token 过期、IP 限流；`robots.txt` 禁止 `/*.json`、`/query/`、`/stock/`，并禁止多类 AI 爬虫；条款还明确禁止将雪球内容用于 AI 系统、RAG 或数据集。
- **合规边界**：只公开帖子；不私信；不把全文喂给外部 LLM、不建数据集；弘信电子案说明虚假帖子可被行政拘留，内容敏感度高。
- **正文/时间**：全文、时间、评论可得；质量高于股吧。
- **难度**：3–5 天；浏览器取 token 或手动 cookie。
- **是否值得**：值得，信号质量高；排在微博之后。

### 3.6 股吧

- **公开获取**：列表页/详情页 HTML，无登录；`robots.txt` 实测 404，无明确规则；GBK 编码。
- **凭据/逆向**：无。
- **反爬/封号**：UA/频控/403；HTML 结构变动；详情页单请求约 2–4 秒。
- **合规边界**：公开帖子；低风险；不存作者个人信息、不转售全文。
- **正文/时间**：列表有标题、阅读、评论、时间；详情有完整 HTML 正文、点赞/评论/图片；`article_list` JSON 提供精确发布时间。
- **难度**：1–2 天。
- **是否值得**：值得，第一优先。

### 3.7 其他公开渠道

- **韭研公社**：公开 SSR 页面，`robots.txt` 允许抓取，sitemap 含约 14.3 万篇文章 URL；文章页实测 35KB，含“小作文”全文与题材标签；无需登录。**强烈建议作为第二优先**，1–2 天可接。
- **财联社/华尔街见闻/新浪 7x24/同花顺/东财快讯**：项目已覆盖，继续作为“事实校验/辟谣层”，不是传闻源。
- **巨潮公告/证监会/交易所/中国互联网联合辟谣平台**：官方澄清是“小作文存在”的强信号；建议 2–3 天接入巨潮 `hisAnnouncement/query` 与辟谣平台，用于影响打分和“辟谣”标签。
- **淘股吧/知乎/抖音/快手**：文本密度低或反爬高，暂不优先。
- **Telegram**：项目已支持 `t.me/s/` 公开预览；对 A 股小作文信号弱，维持现状即可。

## 五、无人工落地排序

| 顺序 | 渠道 | 理由 | 工作量 | 风险 |
|---|---|---|---|---|
| 1 | 股吧详情补抓 | 已有管线、无凭据、立即提升正文质量 | 1–2 天 | 低 |
| 2 | 韭研公社 | 公开 SSR、robots 允许、小作文/纪要密度高 | 1–2 天 | 低 |
| 3 | 公众号 RSS | 文本质量最高；消费现成 RSS 即可 | 0.5–1 天 | 低（依赖第三方） |
| 4 | 微博 | 公共放大层，覆盖最广 | 3–5 天 | 中 |
| 5 | 雪球 | 高质量讨论，虚假帖子可驱动股价 | 3–5 天 | 中 |
| 6 | 小红书 | 散户截图/年轻用户，但高风控 | 5–10 天 | 高 |
| 7 | 微信群 | 无合规无人路径 | N/A | 极高 |

**为什么这样排**：先做“无凭据、低风险、已具备基础设施”的股吧；再做“公开且允许抓取”的韭研；公众号用 RSS 是低成本高收益；微博、雪球需要 cookie/token，放在中期；小红书风险最高，条件性；微信群永不做。

**无人值守设计**：每个源记录 `credential_required / robots_status / risk_level / last_success / next_retry`；凭证失效只告警不重试轰炸；高风险源默认关闭；单源失败不影响全局；对详情请求设 1–2 req/s、并发 5、超时 10s、熔断与缓存。这样“无人”是可持续的，而不是假装零维护。

## 六、股吧详情补抓：成本收益

本次实测：列表页 197KB、20 行，含标题/阅读/评论/时间；详情页 22–24KB、单请求 2.3–4.1 秒，含完整 HTML 正文、点赞/评论/图片。列表页 `article_list` JSON 虽有 85 条记录，但仅 5 条带 203 字预览，**不能替代详情**。

- **收益**：全文 simhash 才能识别“同文多帖/跨源转载”；正文支持实体抽取、传闻词命中、截图 OCR、事件时间线；详情还提供点赞/评论，可作为影响分先验。
- **成本**：每帖多 1 次请求；按 1,000 帖/天、22KB/帖估算约 22MB/天，带宽可忽略；主要成本是解析器、并发、重试与反爬维护，约 1–2 人日。
- **策略**：不要全量补抓。只对“强传闻词/关注标的/阅读≥阈值/评论≥阈值/未去重”的候选补详情；按 `post_id` 缓存；403 即退避；正文清洗后只保留必要片段。
- **结论**：**做，且优先做**。这是当前投入产出比最高的一步。

## 七、风险与合规声明

**司法与监管信号**：腾讯诉斯氏案（60 万，75 个微信号+代理 IP 绕过封禁，违反 robots）；微博诉蚁坊案（528 万，抓取非公开数据并全文展示）；微信数据库解密/群控案（刑事/不正当竞争）；2025-12 CAC/证监会通报（AI 批量“小作文”账号被关闭）。这些案例的共同点是：**绕过技术措施、规模化抓取、全文替代性展示、商业化转售**，而不是“看一眼公开页面”。

**robots 实测**：公众号 `Disallow: /`；小红书 `User-agent: * Disallow: /`；微博 `User-agent: * Disallow: /`（少量 allow）；雪球禁止 `/*.json`、`/query/`、`/stock/` 及 AI 爬虫，条款禁止 AI/RAG/数据集；股吧无有效 robots（404）；韭研 `Disallow:` 为空。robots 不是法律本身，但会成为“是否获得授权、是否善意”的重要证据，尤其腾讯案已明确引用。

**明确不做**：① 微信群/小红书群聊/私信监控与破解；② 微信数据库解密、Hook、Wechaty/iPad 协议、群控；③ 验证码识别/绕过、代理 IP 轮换规避封禁、账号池；④ 抓取登录后/付费/私密内容；⑤ 抓取手机号、微信号等个人信息；⑥ 存储、转售、对外提供全文搜索/镜像；⑦ 用抓取内容训练模型或做 RAG（尤其雪球）；⑧ 生成、润色、传播“小作文”或荐股。

**开源边界**：代码 MIT，但数据不随仓库分发；高风险源做成可选插件、默认关闭、用户自备凭证；不提交 cookie/token/原始帖子；不提供托管多租户服务；README 明确“个人研究、不构成投资建议”。引用 RSSHub（AGPL）、MediaCrawler（非商用）等只学架构，不复制代码。

**LLM 边界**：默认只把标题+短摘要发给外部 LLM；雪球、小红书、公众号全文默认不外发；对抓取内容做 prompt injection 清洗，把内容当数据而非指令；LLM 只做分类/摘要/翻译，不做投资建议。

## 八、结论

TT_Sniffer 不应追求“潜入微信群”，而应成为**公开二级传播层的实时嗅探器 + 官方信息的交叉校验器**。近期先做股吧详情补抓与韭研公社，立刻提升正文质量与信号密度；接着用现成 RSS 接入 20–50 个公众号；再用低频 cookie 接微博、雪球；小红书只在明确需要时做，且必须接受高维护与高风控；微信群保持“不做”，用异动反推和人工转发入口兜底。这样既能保持个人项目的低风险，又能在小作文外泄后的几分钟到几十分钟内捕捉到它。
