# 微信公众号获取路线调研（替换 RSS 自建方案）

**调研时间**：2026-10-24（协议原文核验 + 本机探针实测 + 服务存活盘点）
**背景**：用户否掉自建微信读书转 RSS 路线（封号风险，主号不可冒险），
提出"AI agent 定时模拟真人刷微信摘内容"想法，请求评估并调研更优路线。

## 一、结论先行

1. **"AI 模拟真人"不是护身符**：《腾讯微信软件许可及服务协议》8.2.1.6 与
   《微信个人账号使用规范》1.2.6 禁止的是**手段**（第三方软件自动化操作微信
   并读取界面/数据），不是"看起来像不像人"。模拟真人只降低被发现概率，
   不改变违规性质；且概率不是安全边际——主号损失是非对称的（封号可牵连
   关联账号）。
2. **真正的问题不是"怎么不被封"，而是"谁去冒险"**：公众号正文
   `mp.weixin.qq.com/s/<id>` 无登录无 cookie 直接可取（本机实测 200，
   `js_content`/`js_name`/`ct` 全可得）——**正文层零风险**；难的只是
   **发现层**（谁告诉你出了新文章）。发现层可以外包给平台（今天看啥）、
   降级为人工投喂（官方服务号 API）、或用可弃小号（最差选择）。
3. **推荐组合（主号零参与）**：今天看啥（¥28/月，风控由平台承担，RSS 直插
   `subscriptions/*.yaml`）+ 零凭据正文抓取（按 URL 逐篇、限速、不镜像）
   + 官方投喂兜底（自建认证服务号收消息接口，人工转发链接=分钟级）
   + 转载层（韭研/股吧/微博文中贴出的公众号链接走同一正文抓取）。

## 二、用户想法评价：AI agent 模拟真人操作微信

**方向对的部分**：把抓取变成有界、限频、可暂停的自动化（而非一次性全量），
工程直觉正确；技术底座存在（WeChatAuto.SDK 就是"面向 AI 的微信 RPA"，
带 MCP server）。

**致命问题（按严重度）**：

1. **把"像真人"当合规依据**——条款管手段不管外观（见结论 1）。
2. **风险主体反了**：担险的是主号；拿最有价值的资产换最慢的通道。
3. **AI agent 比脚本更易暴露**：行为画像极其规律（固定时刻、等长间隔、
   只读不点、打开即退）；"像人"反而要求做无意义随机交互=扩大异常面。
4. **微信 4.x 实时渲染**（wxauto 官方博客）：只有屏幕可见区消息进 UIA 树，
   滚出去即销毁；公众号正文是 webview，UIA 拿不到文本必须 OCR——
   单篇 10-30 秒、错误率高、随版本反复返工。
5. **发现面窄**：`mp/profile_ext?action=getmsg` 无 cookie 实测
   `ret:-3 no session`；agent 只能读"已订阅号推来的消息"，
   对调研纪要类首发号覆盖极有限。
6. **时效不匹配**：小作文窗口是几分钟；UI agent+OCR 是分钟-十分钟级且不全。
7. **不可观测**：风控提示滞后突发，无法在主号上"先小规模试"。

**若非要保留（不推荐）的改造**：agent 只做发现不做正文；专用旧安卓机+
无支付无通讯录小号；物理隔离主号；只读不写；每天 1-2 次随机时段；
任何风控提示立即停手。

## 三、五条路线四维评估（摘要）

| 路线 | 可行性 | 谁的号在冒险 | 成本 | 时效 | 结论 |
|---|---|---|---|---|---|
| PC UI 自动化（wxauto/WeChatAuto.SDK/wechaty） | 中低（读公众号正文要自研 OCR；wechaty 免费 web 协议已死） | **主号** | 3-10 人日+版本返工 | 最差 | 不做 |
| 手机自动化/AI 屏幕 agent | 中（安卓无障碍可做；Wechat2RssScript 实测上限=只有链接无全文，锁 8.0.34） | 可弃小号 | 旧手机+5-10 人日 | 差 | 仅小号补漏，主号绝不上 |
| 托管付费（**今天看啥**/Wechat2RSS/WeRSS） | 高 | **今天看啥=平台；Wechat2RSS/WeRSS=你（小号扫码）** | ¥6-90/月 档位 | 小时级，极速订阅可压更低 | **今天看啥为主力** |
| 官方通道 | 服务号"接收消息"投喂=高；搜狗死；微信读书退化（列表接口废弃，配额账号级） | 投喂=零（自己的服务号） | 认证服务号 ¥300/年 | **投喂=分钟级** | **投喂做兜底** |
| 公开 web 分发面 | 正文页零凭据 200；搜索引擎收录不可靠；新榜 B2B 可查历史 | **零** | 低 | 转载层分钟级 | **正文层主干** |

服务存活实测（2026-10-24）：今天看啥 200、Wechat2RSS 200（免费池 390 号、
财经仅 1 个）、we-mp-rss 活跃（5.0k★）、feeddd/wewe-rss/werss.io 已死、
搜狗本机不可达。

## 四、落地建议（增量，不动现有管线）

1. `app/collectors/wechat_mp.py`：输入 URL 列表（RSS/投喂/转载层），零凭据
   抓 `js_content` 正文，限速 1 req/s、按 (biz,mid,idx,sn) 缓存去重、
   只留必要片段、不镜像全文（robots 为 Disallow:/，只取"被给出的单篇
   URL"，腾讯诉斯氏案判例在案）。
2. `subscriptions/*.yaml` 加今天看啥 feed 示例（发现层外包）。
3. 投喂入口：自建认证服务号官方"接收消息"接口（或先用企微/飞书机器人
   webhook 替代验证价值）→ 解析 `mp.weixin.qq.com` 链接 → 入队 → 同一
   正文抓取。主号只做"人工转发链接"这一个动作。
4. 转载层增强：韭研/股吧条目正文中出现的公众号链接顺手入队（已有全文，
   正则抽取零成本）。
5. 配置红线：`wechat_mp.allow_credentialed=false`——永不引入微信登录态。

## 五、明确不做（红线更新）

- 主号运行任何 UI 自动化/无障碍/VLM agent/协议工具（**新增**："AI agent
  模拟真人"同属此类，条款 1.2.6/8.2.1.6 不因交互仿真而豁免）；
- 按"封号阈值"设计自动化频率（wxauto 官方也明确拒绝此承诺）；
- 公众号后台 token+Cookie 批量抓（实测 no session，社区反馈 2026-07 后
  接口已封）；
- 搜狗微信搜索当主通道；对抓取全文做镜像/转售/数据集。
