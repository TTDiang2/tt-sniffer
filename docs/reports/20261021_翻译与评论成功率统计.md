# 20261021 翻译 / 戏谑评论成功率统计（为 key 池定规模）

> 生成：2026-10-21 晚。数据源：`data/sniffer.db`（只读，schema 未动）+ `data/server.log`（补充口径）。
> 目的：量化「LLM 翻译」「一句话戏谑评论」两条通道的成功率与失败原因，为 3–5 个 key 池的规模与路由策略提供依据。

## 一、口径说明（先读这个）

- **翻译**：`app/pipeline.py` 对每条新采集的外网条目（`needs_translation`：源在 `FOREIGN_SOURCES`，或文本拉丁字母≥12 且汉字×2<拉丁）在入库时**一次性调用** `llm.translate()`（单条最多 3 次 HTTP 尝试、含 2 次重试，仅重试 429/5xx/网络/解析类临时故障；评论通道 `enrich` 为单次尝试、无重试）。**没有失败重试队列**——当轮失败即永久失败（条目保持原文）。
- 因此分母可以在 DB 上**精确重建**：对窗口内非回填条目重放 `needs_translation(source, title, text)` 纯函数 = 总尝试条数；`translation` 非空 = 成功。差值 = 失败条数，无遗漏。
- **戏谑评论**：走 `llm.enrich()`（LLM 精筛），prompt 要求输出 `one_line` 戏谑短评。触发条件：非回填、`score >= 55`（`llm.min_score`），webhook 候选全量 + 非候选按分取前 20/轮（`round_cap`）。
- 日志补充口径的局限：`server.log` 行格式**只有时分秒没有日期**（`main.py` datefmt=`%H:%M:%S`）；8787 生产与 8788 隔离实例**共写同一文件**；当前文件仅 2.5MB（未轮转）。故日志数字只作失败原因分布参考，不作分母。

## 四、失败原因分布（server.log 补充口径）

条目级**最终失败**（无「重试」字样行，翻译通道）：

| 原因 | 条数 |
| --- | --- |
| 未知（旧格式无类型行，8787 长驻进程的旧版 llm.py 写入） | 9 |
| ReadTimeout（30s 读超时） | 3 |
| HTTPStatusError 429 Too Many Requests | 3 |
| 返回字段不完整（title_zh 缺失等，判失败） | 3 |

HTTP 层**重试**次（「重试 x/2」行，**仅翻译通道有重试预算**——评论通道 `enrich` 为 `retries=0` 单次尝试）：

| 原因 | 次数 |
| --- | --- |
| ReadTimeout | 34 |
| ConnectError | 9 |
| HTTPStatusError（429） | 6 |

结论：
1. **ReadTimeout 是头号失败原因**（占 HTTP 层失败 ~70%）——上游 `api.agnes-ai.cn` 响应慢或 30s 超时偏紧，与并发信号量（translate 并发 3）叠加。
2. **429 已实际发生**（3 条条目级终败 + 6 次重试）——单 key 在当前负载下已触碰限流，**key 池有实证依据**。
3. ConnectError（上游连接拒绝）零星出现，key 池无法解决，属上游可用性问题。

## 五、key 池规模建议（供决策，非结论）

- 当前 8 小时 290 条尝试 ≈ 36 条/小时峰值段负载；翻译+精筛合计 LLM QPS 远低于 1。
- 429 终败 3/290 ≈ 1%，重试后仍失败说明 429 窗口内持续限流——**2 个 key 轮换即可吸收**；留冗余（其中 1 个被限流时切换）取 **3 个**。
- 路由策略建议：429/5xx → 立即换 key 重试（已有 `_retryable` 判定，换 key 逻辑可挂在同一处）；ReadTimeout → 保持现有 0.8s 退避重试，超时与 key 无关。
- 戏谑评论通道 83.3% 成功率中失败同样以超时为主，key 池对其增益有限；**为翻译通道配轻量模型 + 3 key、评论/对话通道配更强模型**与既定多 key 多模型方案（见 `20261021_多key多模型配置方案.md`）一致。

## 六、回看义务

- 本统计为 8 小时 / 5.4 天窗口的横截面；key 池上线后应重跑本脚本对比 429 归零、ReadTimeout 占比变化。
- `server.log` 无日期的问题若影响后续统计，可单开小任务把 datefmt 补上日期（动 `app/main.py` 一行，重启生效——需用户同意窗口）。
