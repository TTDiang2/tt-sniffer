## 二、F-201：宏观日历与利率快照没有出口

### 现象

- `app/collectors/calendar.py` 持续抓取美国/中国宏观事件，写入 `data/macro.db`。
- `app/collectors/rates_snap.py` 每个交易日抓 CME ZQ 近月/次月结算，写入 `data/rates_snap.jsonl`。
- `app/pipeline.py` 有 `calendar_loop()`、`rates_snap_loop()`，按配置定时执行。
- 但后端没有 `/api/calendar` 之类的接口，前端也没有任何引用；`calendar.read_events()` 没有调用方。
- 采集一直在跑，用户却看不到任何数据。

### 附带成本

`calendar.py` 顶层 `import akshare`，而 `pipeline.py` 会导入它，导致应用启动时就被动加载 akshare，抵消了 quotes 原有的惰性导入。

### 用户已确认方案：方案 A 接线

放置位置：前端“统计”tab（`charts-view.tsx` 所在视图），与现有官方 SEP 点阵排在一起。

要展示的内容：

- 非农、CPI、失业率、FOMC 利率决议
- CPI、PPI、PMI、GDP、社融
- FOMC 会议日程与 SEP 点阵标记

展示形式：

- 适合表格的用表格：日期、国家、指标、期数、前值、预期、实际、修订时间。
- 不适合表格的用数据卡片：例如下一场 FOMC、最近一次非农、SEP 标记。

建议实现：

1. 后端新增只读接口，例如 `GET /api/calendar?days=30&country=US,CN`，返回 `macro_events` 行；再新增 `GET /api/rates` 返回 `rates_snap.jsonl` 最近记录。
2. 前端在统计 tab 增加“宏观日历”区块，按日期分组，实际值到达后展示“预期 vs 实际”，并用颜色区分超预期/不及预期。
3. FOMC 会议与 SEP 只做标记，不重画点阵，避免和现有官方 SEP 图重复。
4. `calendar.py` 的 `akshare` 改为函数内惰性导入，避免启动负担。

验收：

- 统计 tab 能看到未来事件和已公布事件。
- 美国、中国各至少一条含“预期值”的记录可见。
- 刷新页面数据不闪烁，接口失败时区块降级为提示，不影响其他图表。

## 三、F-102/103：启动回填锁死后端

### 现象

`store.Store.__init__` 在 `with self._lock:` 内依次执行：

- `_backfill_hashes`
- `_backfill_simhash`
- `_backfill_impacts`
- `_backfill_groups`

其中 `_backfill_groups` 会全库重算、重放分组，大库可能超过 180 秒。整个期间锁不释放，API 请求和采集线程都被阻塞。

另外 `insert_many` 只对非回填行调用 `_assign_group`，回填行的组信息是单例，`group_key` 与实际不一致。

### 建议方案

1. 把回填移出 `__init__` 的锁，改为启动后的后台任务；`__init__` 只建连接和轻量检查。
2. 回填期间提供“正在进行”的状态，接口读取时若组信息缺失，返回可降级的结果，而不是等锁。
3. `insert_many` 对回填行同样调用 `_assign_group`，或提供统一的分组入口，保证回填与实时路径一致。
4. 大库回填考虑分批提交，每批 sleep 少量时间，避免长时间占用写锁。

验收：

- 启动时 `/healthz` 与主要 API 在回填完成前也能返回。
- 回填完成后 `group_key` 与实时插入结果一致。

## 四、F-106：翻译任务无上限排队，写库阻塞事件循环

### 现象

- `pipeline.py` 中 `translate_sem = Semaphore(3)` 只限制并发，不限制排队数量。
- `_ingest` 对每条 `needs_translation` 的新闻都 `_spawn(_translate_and_broadcast)`，突发时任务数等于新闻条数。
- `set_translation` 在事件循环线程内同步写 SQLite，可能卡住 SSE 推送。

### 用户明确口径

> “还是最终全都有翻译比较好。当然可以降级，不要全都堆在一起翻译，一部分在空闲的时候做就行呗。”

即：

- 最终目标是全部翻译，不丢条目。
- 突发时不要一次性把任务全堆上去，要限量、排队。
- 空闲时继续消费队列。
- 翻译是增强信息，不能拖慢主流程和实时推送。

### 建议方案

1. 引入有界队列（例如 `asyncio.Queue(maxsize=200)`）或待翻译表标记。
2. 入队时若队列满，不丢弃，落库标记 `pending_translation`，由后台 worker 空闲时继续。
3. worker 数量保持 2–3，按配置可调；翻译完成后更新状态并广播。
4. 空闲检测：队列为空且最近 N 秒无新新闻时，主动扫描历史未翻译条目补齐。
5. `set_translation` 用 `asyncio.to_thread` 包裹，避免阻塞事件循环。
6. 指标：待翻译数量、已翻译数量、失败重试次数，便于观察是否积压。

验收：

- 突发 500 条新闻时，SSE 主流程延迟不显著上升。
- 队列最终清空，所有条目都有翻译或明确失败原因。
- 空闲后历史未翻译条目被补齐。

## 五、F-206：FOMC 日程硬编码

### 现象

`calendar.py` 中 `_FOMC_2026` 硬编码 8 次会议，`fomc_events()` 只读取 2026。进入 2027 年后，FOMC 会议与 SEP 标记会静默消失，没有任何告警。

### 建议方案

1. 把 FOMC 日程移到配置文件，或扩展为 2026–2028 多年份数据。
2. 抓不到当前年份日程时写 warning，并在 `/api/calendar` 返回中标记“日程可能过期”。
3. 长期方案：从美联储官网 `fomccalendars.htm` 解析，失败时回退静态配置。
4. SEP 月份（3、6、9、12 月）单独标记，避免把每次会议都当作有 SEP。

验收：

- 跨年时 FOMC 事件不消失。
- 缺年份时有明确告警，而不是静默无数据。

## 六、F-109/207：运行细节泄露

### 现象

- `/healthz` 是公开白名单路径，却返回 `last_ingest`、`subscribers`、`collectors` 等运行细节。
- `/api/ai/status` 需要登录，但返回每个通道的 `model`、`base_url`、`keys_total`、`keys_available`。

### 建议方案

1. 公开 `/healthz` 只返回 `{"status":"ok"}`；详细状态放到需要鉴权的 `/api/status`。
2. `/api/ai/status` 脱敏：不返回 `base_url` 全文，密钥只返回“是否可用/剩余数量”这类聚合值。
3. 若确实需要排查，可在日志中记录，而不是通过接口返回。

验收：

- 未登录访问 `/healthz` 看不到采集/订阅细节。
- `/api/ai/status` 不再暴露 base_url 与密钥数量细节。

## 七、F-208/209：报告归档与内存计数

### 现象

- 根目录有 6 个日期前缀报告，没有索引，查找困难。
- `server.py` 的 `_ai_rate_ok` 使用 `ai_hits` 记录每个 IP 的请求时间，只清理当前 IP 的过期时间戳，不删除 IP key，长期运行会持续增长。
- `auth._FAILURES` 有 5 分钟窗口且空 key 会 pop，风险较小。
- `polymarket._LAST` 已在 F-205 改为只增不清，需配合基线重置日志。

### 建议方案

1. 报告统一移入 `docs/reports/`，根目录保留一个 `docs/README.md` 索引；历史文件名不再改动内容。
2. `ai_hits` 定期清理所有过期 IP key，或改用滑动窗口计数结构。
3. `_LAST` 增加 `baseline_reset` 日志，便于观察掉榜后的基线变化。
4. 评估给关键内存结构加长度上限或定期压缩。

验收：

- 长时间运行后 `ai_hits` 的 key 数量稳定。
- 报告可按索引找到。

## 八、F-210：14 日趋势重复请求

### 现象

`charts-view.tsx` 中 `useEffect(..., [day])` 同时请求：

- `/api/days?days=14`
- `/api/summary?day=...`
- `/api/sentiment?day=...`

其中 14 日趋势与当前 `day` 无关，却随着日期切换重复请求。

### 建议方案

1. 拆成两个 effect：14 日趋势只依赖挂载/显式刷新；当日相关请求依赖 `day`。
2. 或把 14 日数据放在更高层缓存，切日期时复用。
3. 顺带检查是否有重复渲染导致的请求放大。

验收：

- 切换日期时不再请求 `/api/days?days=14`。
- 图表数据不缺、不闪烁。

## 十、F-017：接口使用 store 私有成员

### 现象

`server.py` 的 `/api/dotplot`、`/api/scatter` 直接使用：

- `store._day_range`
- `store._lock`
- `store._conn`

`store.py` 约 953 行，承担了存储、计算、分组等多种职责，属于上帝对象。

### 建议方案

1. 在 `Store` 上增加公共方法，例如 `day_range()`、`query_dotplot(day)`、`query_scatter(day)`，接口只调公共方法。
2. 新查询逻辑优先放在公共方法内，避免继续穿透私有成员。
3. 中长期按职责拆分 store（读写、分组、回填、查询），但不在本轮做大规模重构。

验收：

- `server.py` 不再出现 `store._` 形式的访问。
- 接口行为不变，测试通过。

## 附：行情实时刷新与 USDCNH 调研结论（20261022）

> 本节为只读调研结论，尚未开工。

### 结论一：当前“指数不刷新”的主因不是轮询慢，而是数据源是日线昨收

实测 2026-10-22 13:50（北京时间）：

- `/api/quotes` 返回：上证 3713.028、沪深300 4111.933、恒生 23651.87、纳指 26702.86。
- 同一时刻新浪实时行情：上证 3657.06、沪深300 4033.16、恒生 22919、纳指仍为 10-21 收盘。
- 上证 3713.028、沪深300 4111.933、恒生 23651.87 正好等于 2026-10-21 日线收盘。

原因：

- 多数标的走的是日线接口：`stock_zh_index_daily`、`index_us_stock_sina`、`stock_hk_index_daily_sina`、`futures_foreign_hist`、`bond_zh_us_rate`。
- 这些接口在盘中返回“上一收盘”，不是实时价。
- 只有 KOSPI/日经走东财全球现货，但该接口本身抖动（调研期间 `index_global_spot_em()` 出现 JSONDecodeError）。
- 后台 `TTL_SECONDS=60`、前端 `usePolling(..., 60000)`，即使有实时源，最快也要约 1 分钟才更新。

结论：要给“实时跳动”，需要同时做两件事：

1. 把 A股/恒生/纳指/贵金属/原油换成实时行情源。
2. 把刷新间隔从 60 秒降到 5–10 秒，并由后端统一轮询、前端只读缓存。

### 结论二：USDCNH 可用新浪实时源

新浪 `https://hq.sinajs.cn/list=fx_susdcnh`，请求需带 `Referer: https://finance.sina.com.cn/`。

实测返回：

```text
var hq_str_fx_susdcnh="13:50:24,6.673700,6.674100,6.673700,47,6.674500,6.676200,6.671500,6.673700,离岸人民币（香港）,-0.010000,-0.000100,0.0007042,,6.995700,6.672400,,2026-10-22";
```

解析建议：

- 价格：字段 8（本例 6.673700）。
- 涨跌幅：字段 10（本例 -0.010000，口径为百分比）。
- 涨跌额：字段 11（本例 -0.000100）。
- 日期：最后一个字段（本例 2026-10-22）。
- 时间：字段 0（本例 13:50:24）。

实测两次调用间隔 13 秒，时间戳从 13:49:04 到 13:49:17，确认是实时更新。

其他源对比：

- `ak.forex_spot_em()`：实测 502，继续不可用。
- `ak.forex_hist_em(symbol="USDCNH")`：连接被重置。
- `ak.fx_spot_quote()`：可用，但返回的是在岸 USD/CNY，不是离岸 CNH，且无时间戳。
- 腾讯 `qt.gtimg.cn`：支持 A股/恒生/美股，但不支持 USDCNH，返回 `v_pv_none_match`。

推荐：`_forex_cnh` 改用新浪 `fx_susdcnh`，解析价格与涨跌幅，日期时间由响应字段提供。
