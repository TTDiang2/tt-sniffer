### 5.1 【B】风险×避险·当日新闻点：气泡全挤在边缘

**用户原话**：所有气泡都集中在边缘，怀疑与之前热力图打分过于极端同根同源；检查并修复优化，**若不好修可以直接不要这幅图**，因为【风险×避险·14日轨迹】已经做得挺好。

**根因已定位（不是数据脏，是坐标系退化）**：

- `app/charts.py:27-34` `_side_score()`：某侧方向票均值 = `sum(±1)/n * 100`。只要该侧有任意一张票，均值必为 **±100**；无票返回 `None`。
- `app/charts.py:37-48` `news_point()`：缺失的一侧按 **0** 处理。
- 结论：单条新闻通常只对**一侧**资产有票，于是坐标必然是 `(±100, 0)` 或 `(0, ±100)` —— 所有点都落在**四条坐标轴射线**上。前端 `charts-view.tsx:72-179` `ScatterSvg` 用 `cx/cy` 把 `[-100,100]` 线性映射到绘图区，于是气泡全部贴边。二维信息量接近 0。
- `app/server.py` `api_scatter()` 还按 `(x,y)` 合并簇 → 只有几个簇。
- 「同根同源」判断成立：资产×日情绪矩阵（`charts-view.tsx` `Matrix`，用 `day_sentiment` 分数着色）同样建立在 ±100 的二值票数上，所以热力图也显得极端。

**要求**：先写一个**小样本诊断**（取当天真实 `impacts`，打印 `news_point` 的 x/y 分布），确认上面前述结论，再选修法：

- 方案 1（推荐，保留象限语义）：坐标改为**连续强度**而非二值票——例如 x = 风险侧净票占比×证据量收缩（`tanh`/按票数收缩），y = 观点强度（或反之），并给「单边观点」用空心/箭头样式区分；轴端留白，避免贴框。
- 方案 2（保守）：保留现有坐标，但软化极值（±100 映射到 ±85 区间）、加「仅单边观点」提示文案、图例补充。
- 方案 3（用户已授权的兜底）：若 1、2 都不划算，**移除该卡片**，保留【14 日轨迹】（`mode="trail"`）与矩阵。

**验收**：

- 气泡不再贴边，且散点能区分出「多边/单边」而不是全落在轴上；或卡片已移除且布局无空洞。

## 7. 明确**不要做**的大改（用户已点头）

| 大改                                   | 为什么不做（大白话）                                                    |
| ------------------------------------ | ------------------------------------------------------------- |
| SQLite → PostgreSQL + Redis + Celery | 现在单机单进程就够用；换栈要数据迁移、要运维两套服务，还会让「查询慢」变成「部署难」                    |
| 上多进程 / 多 worker                      | 采集器会重复抓取、SSE 广播会分裂成多路、内存行情缓存会不一致；省下的 0.7s 查询不值得               |
| 前端整体重写 Next.js                       | 现在 Vite+React 已经能出图；重写等于把半年功能全部重做一遍，风险远大于收益                   |
| SSE → WebSocket                      | SSE 断线自动重连、部署简单、够用；换 WS 还要加心跳、重连、鉴权握手                         |
| 所有采集器上 Playwright                    | 能爬到，但重、慢、易被风控盯上；只对「必须执行 JS 且无替代」的页面用                          |
| 向量库 / Embedding 替换 simhash           | 现在的 simhash+数值槽守卫已经够用且零依赖；换向量库要模型、要索引、要 GPU/CPU 预算，还不解决「打分极端」 |
| LLM 全量同步分类/翻译                        | 慢、贵、会把 SSE 主流程拖住；现有「后台队列 + 限流 + 失败重试」更合适                      |

**原则**：只修 CI、行情退避、并发测试这类小口子；**不动数据库、进程模型、前端框架**这三块地基。
