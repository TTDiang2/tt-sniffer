# TT_Sniffer 调研与设计

> 2026-10-02 · 首版调研基于接口实测（本机 akshare 1.18.94 实时验证）
> V0.1.1（同日）：经独立代码审查修订 16 项问题，建立交付前校验关卡，详见文末变更记录。

## 一、问题定义

"小作文"= 未经证实、快速传播、能短期驱动股债价格的市场消息。用户痛点：
重大事件有官方渠道，但**小作文造成的异常波动往往事后一两天才知道**。

小作文的传播链（实测观察与公开报道归纳）：

```
微信群/QQ群（源头，封闭）      ← 信息孤岛，无法合规直接抓取
    ↓ 几分钟~几小时
公开二级传播源（可捕获！）：
  财联社电报（记者求证/快讯，常直接引用"市场传闻"）
  东财/同花顺/新浪 7x24 快讯（转述+辟谣）
  微博财经话题、雪球讨论、东财股吧（散户聚集）
  财经公众号转载、韭研公社/淘股吧（纪要、传闻文本）
    ↓ 半天~数天
官方回应：上市公司澄清公告、监管辟谣、媒体报道
```

**核心结论：源头抓不到，但二级传播层完全可程序化捕获，且通常只比群内晚几分钟。**
对小作文这种"人人转发"的消息，公开层监控的时效损失远小于想象——真正只在单个
小群里传播、从不外泄的消息，本来也不具备驱动市场的能力。

## 二、数据源调研（实测结果）

| 来源 | 接口 | 实测 | 价值 |
|---|---|---|---|
| 财联社电报 | `ak.stock_info_global_cls` | ✅ 出数 | 速度最快的财经快讯，传闻求证高发地 |
| 东财全球快讯 | `ak.stock_info_global_em` | ✅ 单页200条 | 量大覆盖广 |
| 新浪7x24 | `ak.stock_info_global_sina` | ✅ | 快 |
| 同花顺直播 | `ak.stock_info_global_ths` | ✅ | 补充 |
| 盘口异动 | `ak.stock_changes_em` | ✅ 单类千余条 | "价格先动"信号，反推传闻标的 |
| 涨停股池 | `ak.stock_zt_pool_em` | ✅ 52家(9/30) | 代码↔名称缓存、题材联动 |
| 东财人气榜 | `ak.stock_hot_rank_em` | ❌ 接口失效 | 待换端点或 RSSHub |
| 银行间利率 | `ak.rate_interbank` | ⚠️ 签名变更 | 债市资金面异动，二期接 |

**候选扩展源（二期，按性价比排序）**：
1. RSSHub 自部署：微博热搜/财经超话、雪球热帖、部分公众号镜像 —— 一个容器补齐社交层
2. 巨潮资讯网澄清公告 API（公开）：官方澄清=大作文存在的强信号
3. 中国互联网联合辟谣平台（金融板块）：辟谣=反向确认传闻热度
4. 韭研公社/淘股吧：纪要和小作文文本的高发公开地，需自写爬虫
5. 微博搜索 API（关键词：小作文/传闻/求证+股票名）：社交层最大增量

## 三、架构

```
collectors(异步循环) → 归一化Item → md5去重 → 规则打分 ─→ SQLite
  news.py  四路快讯                                │
  anomaly.py 盘口异动 ──┐                          ├→ SSE广播 → Web单页
  ztpool.py  涨停池    └→ 异动代码集(30min) ──关联加分┤
                                                    └→ webhook告警
                                        LLM精筛(可选,只处理≥55分)
```

设计原则：
- **召回优先**：规则引擎宁可多报，人工看一眼的成本低；LLM 只精筛高分条目省额度。
- **水位去重**：每来源记录时间水位，重启后静默回填不刷屏。
- **接口防腐**：akshare 偶发失效是常态，采集器失败只记日志下轮重试，单源故障不影响全局。

## 四、微信群孤岛问题的应对（明确不做与怎么做）

**不做**：wechaty/iPad协议/群机器人等协议破解方案——违反微信服务条款，封号风险高，
且涉及获取他人私密群聊内容的合规灰区。

**做**：
1. **公开二级传播源监控**（已实现）：小作文要影响市场必然外泄，泄漏点即捕获点。
2. **异动反推**（已实现基础版）：价格/成交量先异动 → 反查该标的的公开讨论，
   "无消息的异动"本身就是小作文存在的最强信号。二期可加"异动但无新闻"自动标记。
3. **人工转发入口**（二期规划）：给用户提供一个 30 秒转发路径——
   微信里看到小作文 → 转发到自己的企业微信机器人/邮件到本地 → OCR+入库打标。
   你就是你自己信息网络的采集节点，工具负责聚合去重打分。

## 五、演进路线

- **V0.1（当前）**：四路快讯 + 规则打分 + 异动联动 + Web单页 + 可选LLM/webhook
- **V0.2**：RSSHub 社交层（微博/雪球/公众号）、澄清公告源、simhash 近重复聚类
  （同一传闻多源转载合并为事件簇，计算传播热度）、人工转发入口
- **V0.3**：债市纵深——银行间利率/国债期货异动监控、资金面关键词专项面板；
  "异动无新闻"探测器；事件时间线回放（某传闻从首现→发酵→辟谣的全链路）
- **远期**：历史小作文库回测（传闻类条目 vs 后续澄清公告的命中率），
  形成"哪些类型的传闻值得当真"的个人经验数据

## 六、合规与边界

- 仅聚合公开信息，个人使用；不存储个人身份信息，不做商用转售。
- 识别结果≠事实，传闻可能完全虚假；辟谣/澄清类条目与传闻条目同屏展示，
  帮助交叉判断。
- 一切内容不构成投资建议。

## 八、V0.2 变更记录（吸收同源实现 + UI 重做）

另一实现（TT_Sniffer_another_agent.zip）经评审后部分吸收：

1. **数据源 +1**：华尔街见闻 7x24（直连官方 API，脱离 akshare 依赖）。
2. **词表校准成果搬运**：其"据悉/有望/知情人士是正规新闻标准信源表述，不能当强
   传闻词"的回测结论与我们的强弱分层一致；新增其贡献的强词（独家获悉/爆料/疯传/
   产业链人士…）与债市弱词（DR007/现券/利率债…）。
3. **市场关联门槛**（其 is_suspicious 设计）：命中强传闻词还需关联可交易标的/市场
   （代码、市场词表、impact 词）才入传闻流，辟谣豁免——解决国际政治类噪音误报。
4. **推送三格式**：企业微信/钉钉（markdown）/飞书（text），app/push.py。
5. **content_hash 跨源指纹**：为"同一传闻多源转载聚合成事件簇"（其 narrative 模型）
   预留数据；去重显示策略与聚类留待 V0.3。
6. 其调研文档确认了我方合规边界：微信采集唯一低风险路线是"离线只读本地库"，
   协议/hook/无障碍路线全部高风险，坚持不做。
7. 其 UI 的优秀交互吸收：新消息悬浮条、正文折叠、分数分档配色、来源多选 chips。

**UI 重做**（按 Anthropic 官方 frontend-design skill 流程：设计规划→反模式自检→实现
→截图自审）：深色终端谱系但去模板化——衬线字体承载品牌与日期数字、四语义色分工
（传闻红/辟谣青/官方蓝/关注金）、**14日传闻热度条**作为唯一装饰性记忆点（兼日历导航）、
左轨色行式列表替代圆角卡片阵列、动效仅新条目渐隐+浮条过渡。多天收纳：‹今天›导航 +
date picker + 热度条 + `?day=` 深链；查看历史时新消息走悬浮条不打断阅读。

**过程中发现并修复的真实缺陷**：
- 首轮回填 300+ 条时 store 逐条 commit 且在事件循环线程执行，阻塞 API/SSE 数秒
  → insert_many 单事务 + synchronous=NORMAL + _ingest 挪入工作线程；
- 前端 fetch 无超时，个别请求停滞时页面永远卡在加载态 → fetchOk（8s 超时+一次重试），
  且侧栏面板与信息流解耦，任何一块失败不拖死首屏；
- 市场门槛上线前的国际噪音误报（"阿联酋航班授权"命中"有消息称"）→ 三折封顶处理。

校验：38 个离线单元测试 + 联网冒烟 5/5；界面三状态 Chrome 截图验收。

## 九、V0.3 变更记录（20261002 夜：正确性清偿 + UI 情报台重做 + simhash）

六项正确性债清偿（智者 A1 门有条件放行→条件清偿）：LLM 精筛漏斗
（broadcast_cap 挤掉条目仍上精筛 + 每轮 round_cap=20 防爆发轮烧配额，
webhook 候选豁免限额）、anomaly"时间"列行级容错、DB 滚动清理
（30 天 retention + 每日 wal_checkpoint(TRUNCATE)）、reload 时序令牌、
limit 负数钳位、date picker max。

UI 情报台重做（用户点名八账全清）：组合检索（关键词+分类+来源多选+
分数档+排序，URL 深链全同步）、服务端分页（offset+total，无限滚动+
按钮双通道）、辟谣对撞块（红绿相邻，速览记忆点）、最高分 Top 榜+
构成词可点检索、统计栏（分时/来源/分类/热词）、ledger 行式终端视觉。
配套后端：/api/items 增 offset/sort/分数档/sources 参数（LIKE 通配符
转义）、/api/summary 单日聚合、/api/collide 辟谣对撞配对。

simhash 最小数据层版：64 位指纹（CJK bigram+ASCII 词）带符号存储、
items.simhash 幂等迁移+启动回填、cluster_size 查询期附加（ts±1 天窗
线性 hamming；鸽笼带预筛对阈值 12 无召回保证，弃用）、数字槽冲突守卫
（digit_conflict：两侧有数字且交集为空=冲突）。**阈值标定如实入档**：
hamming≤12 与真转载档重叠的同模板档实测假阳性 ~10%，守卫剔除其中数字
互斥类别（目标价/预算年模板对）；**残差两类原理上不可分**——共享日期/
月份数字的同模板对（"9月非农4.6万 vs 2.9万"共享'9'）与数字集相同仅
方向反转的对（"从280下调至250" vs "从250上调至280"），实库风险带残差
约 5-6/100 对。badge 定位=转载数提示，非精确断言。

**守卫引入成本更正账目（智者门 2 终审 R 条件，史册以此为准）**：守卫
首轮全量对账申报"剔除 4 对均为点名模板档"有误——第 4 对系纽约期金
4159.60(sina) vs 纽约金 4159.48(wscn)，属**同事件异快照对**（两句独立
成稿、价格相异），按"数字是事实槽"语义不聚簇自洽，但它是守卫的假阴性
成本，非模板档。另：终审申报中"两年期 vs 2-7年期系同稿转载"的申辩
**撤回**——全文对质为方向相反、时刻不同的两条独立快讯（em 20:35 下跌
vs sina 22:59 上行），属假阳性，恰落入已入档"共享数字不可分"残差带。
保留集真残差独立复测 5 对/100 ≈ 5%，全部在上述两类不可分带内。
（门 2 遗留 C3 三项——对撞配对收紧、ORDER BY tiebreaker、SSE payload
带 cluster_size——下轮迭代首笔清偿。）

## 七、V0.1.1 变更记录（独立审查驱动）

独立代码审查发现 V0.1 存在 16 项问题，其中 4 个"点一下就会发现"的缺陷：
关注页签空转、初始排序颠倒、异动关联只认字面代码（名称路径失效）、
LLM 判定不实时上卡；以及评分饱和（普通新闻即满分、辟谣双计）、
水位去重丢同秒条目、akshare 无超时可耗尽线程池、单行坏数据毒死整轮等。
修复要点：

1. 打分引擎重构：传闻词分强/弱两层（强词才归类，弱词只加分）、辟谣不再叠加
   传闻词分、各词表封顶、正则长词优先、AI/ST 加英文边界、代码正则补北交所。
2. 采集器健壮化：逐行解析容错（坏行跳过计数）、`_dt` 兼容 date/time/datetime/str
   列类型漂移（实测财联社接口当日即发生漂移，被新关卡捕获）、全部调用 45s 超时。
3. 流水线：水位改 `<` 防丢同秒条目、异动关联改为"字面代码∪名称命中"、
   后台任务持强引用、webhook 增加候选条件+同标的10分钟节流+LLM 判定拦截。
4. 前端：关注页签走服务端 watch 过滤映射、初始加载与 SSE 方向一致（最新在顶）、
   LLM 判定按卡片 id 实时插入、AudioContext 单例、SSE 断线后全量补偿。
5. 校验关卡（scripts/check.py）：语法编译→包导入→26 个离线单元测试→可选联网冒烟，
   5 项全过才可交付；本机验证版本快照 requirements-freeze.txt。
6. 界面经 Chrome 无头渲染实测验收（docs/screenshot.png），真实数据下误报率
   显著下降（269 条实时数据 7 传闻，旧引擎 260 条 19 传闻）。

第二轮复审追加整改（3 项阻断 + 4 项顺手修复）：

7. LLM 精筛与 webhook 解耦：分数达 min_score 即触发精筛上卡（不再要求配置
   webhook）；webhook 候选在精筛完成后决策，未达精筛线的候选直发——README
   承诺与实现一致，并补 3 个测试覆盖拦截/放行/无 webhook 场景。
8. LLM 判定行 confidence 未转义（XSS 缺口）→ 前端两处补 esc()。
9. 清空夹带旧引擎评分残留的生产库（data/ 运行时自动重建）。
10. watch 语义严格化：异动关联只加分打关键词，不再混入 targets/watch；
    高分条目豁免 broadcast_cap；前端红框阈值改为读 /api/stats 下发（默认80）；
    代码正则补 2 开头（深市B股）；盘口异动单行容错；README webhook 措辞
    收敛为企业微信/钉钉。
